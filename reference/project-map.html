项目地图

按责任和调用链查找代码，而不是按文件名漫游。适合打印或在改代码前快速复习。

当前版本：0.2.2 Vue 3 + Tauri 2 + Rust 更新依据：当前工作区源码
一句话架构： Vue 负责呈现和交互，Pinia/Composables 负责前端状态与副作用，Tauri 命令守住登录与原生边界， ncm-api-rs 负责网易云协议；真正的音频播放仍发生在 WebView。

目录职责

src/views/

路由页面。组织页面级数据获取和组件组合，不应承载底层协议。

入口：DailyRecommend、Search、MyPlaylists、PlaylistDetail、Login、NowPlaying、DesktopLyrics。

src/components/

可复用界面块。播放器栏、歌曲列表、歌词面板、侧栏、队列抽屉等。

症状只涉及渲染或手势时，从这里开始。

src/stores/

跨组件业务状态：用户、播放器（薄 adapter）、主题、桌面歌词窗口。

问“谁拥有这个状态？”时先看 Store；播放状态的真正主人是 Playback Engine。

src/playback/

无框架播放引擎：队列/播放模式、Media Generation 代际隔离、URL 缓存、自动切歌，及 HTMLAudio runtime 与 MediaSession adapter。

播放行为问题都从这里开始；引擎可用 fake runtime 直接单测。

src/composables/

有响应式状态或生命周期的可复用逻辑：歌词、查询缓存、窗口桥接与几何信息。

副作用和浏览器/Tauri API 通常在这里。

src/utils/

尽量纯的转换与计算：LRC 解析、时间轴、格式化、密码 MD5、封面 URL、主题色。

纯输入输出逻辑最适合直接单元测试。

src-tauri/src/commands/

前端可调用的原生命令，按 auth、music、user、lyric、window_geom 分组。

负责验证、调用 API、把动态 JSON 映射为稳定 DTO。

src-tauri/src/state.rs

Rust 全局共享状态：带 Cookie 的 ApiClient、轻量登录态与启动恢复同步。

锁顺序规则也在这里：先取 auth/cookie，再锁 api，避免 ABBA 死锁。

ncm-api-rs/

内置 Cargo 路径依赖，封装网易云端点、Cookie、设备指纹和 weapi/eapi 等加密。

它可选地支持独立 HTTP server，但不是 nnplayer 的运行前置服务。

五条必须会讲的主流程

流程 调用骨架 关键不变量
启动 main.rs → lib.rs::run → Tauri setup / restore；WebView 中 main.ts → Pinia → refresh → Router → App Rust 恢复校验完成前，持久化会话不能被暴露成已登录。
登录恢复 user.refresh → get_auth_state → 等待 restore_session → Router guard 决定跳转 前端保存显示状态；Rust 保存可信 Cookie 与授权状态。
搜索 Search.doSearch → Query Cache → searchSongs → Rust search_songs → cloudsearch 缓存按 auth epoch 隔离，换账号后旧响应不能污染新会话。
播放 SongList → Player Store（薄 adapter）→ Playback Engine → get_song_url → song_url_v1 → Audio.play 引擎统一管队列与媒体副作用；Store 只装配和镜像状态；Rust 只返回 URL DTO。
歌词 当前歌曲变化 → useLyric 拉取/解析 LRC 或 YRC → 读取权威音频时钟 → 面板渲染 / 跨窗口快照 歌词时间来自播放器媒体时钟，不另造独立计时器。

推荐阅读顺序

  1. README.md：只读功能、架构、目录与开发命令。
  2. src/main.ts → src/App.vue → router/index.ts：建立前端骨架。
  3. SongList.vue → player.ts → playbackEngine.ts：读完一条真实功能链。
  4. useNcmApi.ts 与 src-tauri/src/lib.rs：对齐前端命令名和 Rust 注册表。
  5. state.rs 与 commands/music.rs：理解可信状态和 DTO 边界。
  6. song_url_v1.rs → request.rs：只沿调用链进入 API crate。
  7. useLyric.ts 与 歌词排障文档：最后进入较复杂的歌词子系统。
  8. tests/：用现有播放引擎、歌词解析与主题 token 测试理解项目的可验证边界。
暂时不要从这些地方开始： node_modules/、dist/、生成产物、整份 styles.css，以及 ncm-api-rs/src/api/ 下数百个未被应用调用的端点。它们会放大阅读量，却不会先给你主干。
